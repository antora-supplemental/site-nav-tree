= Changelog

== 0.6.8 - 2026-10-17

=== Fixed

* **Overview leaf owns the landing highlight.** `pickBestCurrentPageItem` no longer prefers the shallowest match on component landings: the component root and its Overview leaf share one URL, and only the Overview leaf keeps `is-current-page` (the root keeps `is-current-path` only). Unlinked section labels on the current path no longer paint current-page chrome, so a folder and its Overview do not both look selected.
* **Section breadcrumb crumbs link again.** Promoted section landings are unlinked in the tree, so Antora rendered their breadcrumb crumb as plain text (e.g. Docs site). `siteNavTreeCurrent` now re-links plain-text trail crumbs that match a section label to that section's Overview href, on hard load and after SoftNav swaps.

== 0.6.7 - 2026-10-17

=== Fixed

* **Dual current-page chrome (parent + child).** `siteNavTreeCurrent` now strips `is-current-page` from every nav item except the single winner (including ancestors that only get `is-current-path`). `markCurrentByPath` runs the full current-path rewrite after picking the owner-forest match so SoftNav leaves no stale Antora markers.

== 0.6.6 - 2026-10-17

=== Fixed

* **Cross-forest current-page + partial forest expand.** `pickBestCurrentPageItem` resolves the owning depth-0 forest root from the live menu DOM (not only href prefix on each candidate), prefers shallowest match on component landing URLs, and `markCurrentByPath` absolutizes hrefs before matching. Component landing pages expand every depth-1 section under the forest root after path restore (and on depth-0 label click) so GK Diátaxis branches are not a stale `expanded-v2` subset.

== 0.6.5 - 2026-10-17

=== Fixed

* **Stale companion JS on CDN.** Script injection now appends `?v=<package version>` to `site-nav-tree-current.js` so edge caches (Cloudflare `max-age=14400` on docs hubs) pick up fixes without waiting for TTL. `injectSiteNavTreeUi` skips injecting a second script tag when the hub footer already references the companion (avoids duplicate loads).

== 0.6.4 - 2026-10-17

=== Fixed

* **Cross-component nav xrefs stole current-page highlight.** `siteNavTreeCurrent` / `markCurrentByPath` preferred the deepest `is-current-page` match for a URL. Hub forests duplicate landing URLs when a component nav cross-links another root (Platforms → DevCentr → General Knowledge). Clicking the General Knowledge component root then highlighted the xref under Platforms while article content was correct. Current-page selection now prefers matches under the forest component root that owns the pathname (prefix), then deepest within that subtree.

== 0.6.3 - 2026-10-17

=== Fixed

* **SoftNav intermittent nav 404s.** v0.6.2 froze hrefs once using `window.location` at first paint; rapid SoftNav clicks still resolved stale *relative* `href` attributes against the current article URL, and 404 hydration absolutized against the error page instead of the fetched start page. Nav base is now stored on the panel (`data-snt-nav-base`); `prepareNavMenu` re-normalizes any remaining relative links before each navigation; `siteNavTreeResolveNavLink` resolves click targets for SoftNav; duplicate helper definitions removed from the companion script.

== 0.6.2 - 2026-10-17

=== Fixed

* **SoftNav stale relative nav hrefs.** Antora emits nav links relative to the page that built the tree; SoftNav keeps the live forest DOM, so same-component clicks after a swap resolved siblings against the wrong directory (Explanation → Internet Architecture Overview loops, nested **Internet Reliability** / **Languages** / **Architecture** leaves 404ing with doubled path segments). `site-nav-tree-current.js` now freezes each forest to site-root pathnames on first paint (`data-snt-hrefs-absolutized`); helpers `siteNavTreeAbsolutizeNavHrefs` / `siteNavTreePrepareNavMenu` for full nav-panel replace.
* **404 sidebar empty.** Static Antora 404 pages ship without `page.navigation`; companion JS hydrates the nav panel from the site start page (`/home/` or the article’s start link) so the forest is usable on error pages.

== 0.6.1 - 2026-10-17

=== Fixed

* Overview-landing **unlinked** section labels (Core, Extensions) get Valentus nav-tree hover/focus chrome via `.snt-overview-label` and companion CSS (`site-nav-tree-overview-label.css`), matching linked component roots (`.nav-link`) without reintroducing duplicate-URL `is-current-page` collisions from v0.5.2.
* Parent-label navigation uses `SoftNav.navigate` when available instead of synthetic `overview.click()`, and suppresses redundant hard reloads when the reader is already on the Overview URL (component root click while SoftNav `samePath` leaves the anchor default action live).

== 0.6.0 - 2026-10-17

=== Added

* **Parent label = Overview.** In `site-nav-tree-current.js`, clicking the label of any nav node that has a direct **Overview** (or **Home**) child link now expands the node (never collapses; the caret still toggles) and opens that Overview article. Unlinked section labels (Core, Extensions) activate the Overview anchor, so SoftNav handles it like a normal nav-link click. Linked component roots (Demo pages, Tools, Platforms) expand, then navigate; if the root URL differs from its Overview URL the click is redirected to Overview. Expansion is persisted with the existing `sessionStorage` state. Modified clicks, the caret button, and nodes without an Overview child keep stock Default UI behavior.
* `window.siteNavTreeOverviewLink(li)` helper; tests in `test/nav-label-overview.test.js`.
