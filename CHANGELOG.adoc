= Changelog

== 0.5.1 - 2026-09-26

* Flatten **multiple** anonymous Antora nav trees by concatenating their items (Tools multi-module nav no longer collapses to Overview-only empty wrappers).
* Recursively unwrap **Overview/Home** linked parents that nest sibling articles (Platforms `devcentr.org` Overview-wrap class of bug); Overview stays a peer leaf.


== 0.5.0 - 2026-09-26

* Prefer **Overview** over **Home** when unwrapping a start-page duplicate under a forest root (avoids colliding with a Home component).
* Synthesize an **Overview** child when the component start URL is set but nav has no Home/Overview leaf (parity for General Knowledge, Platforms, Tools, Templates).
* `isHomeNavItem` still treats both labels as the landing slot for hard-sort / root URL preference.


== 2026-09-25 -- Cite facto-stack

* Related link: `antora-facto` renamed to https://github.com/antora-supplemental/facto-stack[facto-stack].
== 0.4.1 - 2026-09-25

* Companion `site-nav-tree-current.js`: persist/restore `.nav-panel-menu` scrollTop via `sessionStorage` (`site-nav-tree:scroll-y`) so SoftNav swaps and full navigations keep left-rail position independently of the content column.
== 0.4.0 - 2026-09-25

* **Home then Changelog hard-sort:** after unwrap, keep a **Home** child (rename start-page duplicates instead of dropping them) and hard-sort each branch Home → Activity Log/Changelog → rest (recursive).
* Component root URL prefers the Home child when present.
* Companion `site-nav-tree-current.js`: expand keys use pathname-only (`site-nav-tree:expanded-v2`) so SoftNav depth / absolutize no longer looks like inject/remove; restore expansion on `SoftNav.loaded` without collapsing non-current siblings.
* Regression: titled multi-origin platform trees stay as siblings under a Platforms hub root.
